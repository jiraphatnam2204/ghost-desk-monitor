1. PROBLEM AND TARGET USERS

During examination periods, many university library desks are held with
belongings (bags, books) while their owners are away for long periods.
Students who need a seat cannot find one, and library staff have neither
the data nor the time to check every desk. QR seat-booking systems record
that a desk was booked, not whether anyone is actually sitting there.

Ghost-Desk Monitor puts a sensor node on each desk that checks whether a
person is really seated and turns a three-face sign (in use / away /
free). There is no booking, no check-in and no app login. A desk left with
belongings gets a LINE warning at 20 minutes and is released at 30
minutes; a desk left clear is released at once.

  -------------------------  ------------------------------  ------------------------------
  Students looking for a     See at a glance which desks     Sign on every desk and a live
  seat                       are really free                 room map on the web

                             losing the desk                 warning at 20 minutes

2. BLOCK DIAGRAM

  SENSOR NODE x2 (per desk)          GATEWAY x1                     CLOUD
  FireBeetle 2 ESP32-S3              YD-ESP32-23 (ESP32-S3)         Supabase
  - LD2410 mmWave (UART, OUT->ISR)   - SCD41 CO2 (I2C)              Postgres + REST
  - VL53L1X ToF (I2C)                - BH1750 light (I2C)           + Realtime
  - OV2640 camera (photo on request) - MAX4466 mic (ADC1)                |
  - Servo 270 deg -> prism sign      - AI model (Edge Impulse, E7)       | Realtime
  - FreeRTOS, 5 tasks                - state machine + timers            v
            |                                  |                    DASHBOARD
            |-- ESP-NOW batch, 1/s ----------->|-- HTTPS (TLS) -->  room map +
            |<- SET_SIGN / SNAP, ack ----------|                    staff page
            |-- 1 photo, HTTP on Wi-Fi ------->|
                                               |-- HTTPS --> Cloud vision API
                                               |             (empty / person /
                                               |              items_only)
                                               |-- HTTPS --> LINE Messaging API
                                                             (warning at 20 min)

- The node reads radar energy per 0.75 m range gate and the ToF distance
  10 times a second and sends one 210-byte batch (with node_id) a second.
- AI 1 on the gateway (E7, M4): an Edge Impulse model trained on our radar
  + ToF data reads the last 5 s of each desk and answers person / empty /
  nearby. Breathing over time separates a seated person from a bag on the
  chair or someone at the next desk. "person" for 60 s -> IN USE.
- AI 2 in the cloud (M4): no person for 2 min -> one photo to a vision
  model: empty -> FREE at once; items_only -> AWAY (LINE at 20 min, freed
  at 30 min with a staff flag); person -> IN USE. No answer in 10 s ->
  plain 30-minute rule. Photos are not stored.
- The gateway sends SET_SIGN and the servo turns the sign.

4. EMBEDDED ENGINEERING DEPTH ITEMS (SECTION 5, II')

  E1  RTOS multitasking   FreeRTOS on the node with five tasks (radar, ToF,
                          radio, camera, sign) with reasoned priorities,
                          exchanging readings through a queue; a mutex
                          protects the I2C bus.
  E2  Interrupt-driven    The LD2410 OUT pin fires an ISR that gives a
      I/O                 semaphore to wake the radar task (no polling).
  E4  Reliable            ESP-NOW acknowledgement from the send callback with
      communication       up to 3 retries and sequence numbers; the gateway
                          buffers rows in RAM while offline and forwards them
                          when the Internet returns.
  E5  Security            HTTPS/TLS to Supabase, LINE and the vision API;
                          Wi-Fi password, API keys and LINE token kept in an
                          uncommitted secrets.h.
  E7  On-device AI        Edge Impulse classifier on the gateway ESP32-S3
                          (allowed by FAQ 4), trained on our own radar and
                          ToF data; it must beat a hand-written threshold
                          rule on the same test set. Reviewed on 13 Nov.
  Spare: E6 OTA update    ArduinoOTA, used instead of E7 if the model does
                          not pass the 13 Nov review.
